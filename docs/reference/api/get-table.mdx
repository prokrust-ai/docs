Read one table definition and its current status from your installation. Use this method to check which columns and source a table uses. The method returns configuration and metadata. Reading source rows requires a separate operation.

<RpcPath />

## Example request

Set `PROKRUST_URL` to your installation's HTTPS origin. Set `PROKRUST_TOKEN` to a Kubernetes bearer token with read access to the table. Set `WORKSPACE` to the table's namespace. Set `TABLE_NAME` to its Kubernetes resource name.

<GuideRequest method="CatalogService/GetTable" body={{namespace: '${WORKSPACE}', name: '${TABLE_NAME}'}} />

To read another table in the same workspace, change `name`. To read a table in another workspace, change `namespace` as well. The pair identifies one table. [Request fields](#request-fields)

### Request headers

| Header | Purpose |
| --- | --- |
| `Authorization` | `Bearer` sends the Kubernetes token for this caller. Use a token with access to the target workspace. |
| `Content-Type` | `application/json` selects JSON encoding for the body. Keep it for these JSON requests. |
| `Connect-Protocol-Version` | `1` identifies the Connect protocol version used by this HTTP request. Keep this value when you change the table or connector. |

## Request fields

Both fields are required. Field names and types come from control schema <code>{releases.control.schemaVersion}</code>.

<RpcFields direction="request" descriptions={{
  namespace: "Kubernetes namespace that contains the table. Use the workload namespace when a cluster has separate system and workspace namespaces.",
  name: "Kubernetes resource name of the table in that namespace. Use the table name even when its source dataset has a different name.",
}} />

## Example response

This excerpt shows the table created in the [synthetic quickstart](/user/synthetic-table/) in a workspace named `team-a`.

```json
{
  "namespace": "team-a",
  "name": "events",
  "spec": {
    "primaryKey": "event_id"
  }
}
```

`namespace` and `name` identify the table the server found. `spec` holds its saved definition. `spec.primaryKey` names the column that identifies each row. Check this value when two columns could serve as identifiers. To select a different key, edit the table definition. [Table primary key](/reference/kubernetes/data.prokrust.ai/v1beta1/table/#primarykey)

## Response fields

These fields report what Kubernetes stored at the time of the read. Use `spec` to inspect the table definition. Use `status`, when present, to inspect controller observations. [Table specification](/reference/kubernetes/data.prokrust.ai/v1beta1/table/#spec) · [Table status](/reference/kubernetes/data.prokrust.ai/v1beta1/table/#status)

## Errors

| Connect code | What to check |
| --- | --- |
| `invalid_argument` | Supply a valid namespace and table name. |
| `unauthenticated` | Use a valid Kubernetes bearer token for this installation. |
| `not_found` | Check that the table exists in the requested namespace. |
| `permission_denied` | Check the caller's permission to get `tables.data.prokrust.ai` in that namespace. |
