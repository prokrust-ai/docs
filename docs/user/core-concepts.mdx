A Prokrust table describes data that you want to use in a graph or a model. To define a table, choose a workspace, a connection, and the data to read.

## Workspaces

A workspace is a Kubernetes namespace enrolled in a Prokrust installation. It holds your connections and tables. A table uses a connection in its own workspace. Two workspaces can each have a table with the same name. Select the workspace that holds the connection you need. [Prepare a workspace](/operator/workspaces/)

## Connections and selectors

A **connector** is the software that knows how to read a particular type of source. A **connection** is a named resource that configures access to a source in your workspace. For example, an S3 connection identifies a bucket and the prefix it can read. A BigQuery connection identifies a project and the datasets it can read.

A **selector** identifies the data for one table within that connection's scope. The connector defines which selector fields it accepts. For example, two tables can share an S3 connection. One can select the object `exports/orders.parquet`. The other can select the object `exports/returns.parquet`. Both use the bucket and credentials from the same connection.

To read another object in the same scope, change the selector. To read from a different bucket, choose a connection for that bucket. [Source selector fields and examples](/user/create-a-table/#source-selector)

## Tables and snapshots

The table definition combines the source selection with a column schema. Each column has a physical type and a role. For example, an order number stored as text has physical type `Utf8`. Give it the role `Id` if you use it to identify an order. A measurement stored as a floating-point number can have physical type `Float64` and role `Numerical`.

The primary key identifies one row. If an order can contain several line items, the order number alone cannot identify a line item. Use a unique line-item identifier for a table with one row per line item.

Creating a table saves this definition. Creating a table snapshot reads the selected source and produces a version of the table data for subsequent work. Use the definition to check which columns Prokrust expects. Use a snapshot when you need the data itself.
