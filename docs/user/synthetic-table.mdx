Create a table and verify its stored definition. The synthetic connector generates the source files inside the cluster. You can complete this quickstart without external storage or source credentials. For your own data, see [Create a table](/user/create-a-table/).

Use an [enrolled workspace](/operator/workspaces/) with the [synthetic connector](/reference/connectors/synthetic/1.1.0-rc.1/) enabled. You need permission to create synthetic connections and to create and read tables. This example uses the connection name `fixture` and the table name `events`. Both names must be available in your workspace.

## Create the connection

Create a source of 128 rows in two CSV files. The fixed seed lets you repeat a test with the same values.

<ActionTabs>
<TabItem value="ui">

1. Select your workspace in the Prokrust app.
2. Open **Data → Connections → Create connection**.
3. Select the synthetic connection type.
4. Enter `fixture` for the connection name.
5. Under **Provider configuration**, set the seed to `42`, the partitions to `2`, and the rows per partition to `64`.
6. Select **Save connection**.

</TabItem>
<TabItem value="k8s">

Set `WORKSPACE` to your workspace namespace. Copy this manifest into `fixture.yaml`.

<CodeBlock language="yaml" title="fixture.yaml">{connectionYaml}</CodeBlock>

`apiVersion` and `kind` identify the installed synthetic connection type. `metadata.name` is the name your table will use to find it. See [connection fields](#connection-settings) for the three generator settings under `spec`.

```bash
kubectl create -n "$WORKSPACE" -f fixture.yaml
```

</TabItem>
<TabItem value="curl">

Set `PROKRUST_URL` to your installation’s HTTPS origin. Set `PROKRUST_TOKEN` to your Kubernetes bearer token. Set `WORKSPACE` to your workspace namespace.

<GuideRequest method="ProviderCatalogService/CreateSourceConnection" body={requests.fixture} />

`namespace` and `name` identify the new connection. The fields `type.apiVersion` and `type.kind` select the installed Kubernetes connection type.
This method carries the generator settings as bytes. `specJson` is the base64 encoding of the UTF-8 text `{"seed":42,"partitions":2,"rowsPerPartition":64}`. If you change a setting for a new connection, encode the new JSON. See [connection fields](#connection-settings) and [request headers](/reference/api/get-table/#request-headers).

</TabItem>
</ActionTabs>

### Connection settings

| Generator field | Why this value |
| --- | --- |
| `spec.seed` | `42` fixes the generated values. Choose another seed for a different set of numbers. |
| `spec.partitions` | `2` puts the rows in two files. Use one partition to test a single file. |
| `spec.rowsPerPartition` | `64` sets the size of each file in data rows. Increase it to test with more rows. |

All three values are fixed when you create the connection. [Accepted ranges and empty files](/reference/connectors/synthetic/1.1.0-rc.1/#connection-fields)

## Create the table

The connector exposes one dataset, `events`. Use its `event_id` column as the key. Expose its `value` column as a numerical feature named `reading`.

<ActionTabs>
<TabItem value="ui">

1. In the workspace that contains `fixture`, open **Data → Tables → Create Table**.
2. Enter `events` for **Table name**.
3. Under **Source and discovery**, select the synthetic connection type and the `fixture` connection.
4. If the app asks for a selector version, select `v1`. Then choose the `events` dataset.
5. Add these columns.

   | Name | Physical type | Semantic role | Feature |
   | --- | --- | --- | --- |
   | `event_id` | `Utf8` | `Id` | Off |
   | `reading` | `Float64` | `Numerical` | On |

   See [table settings](#table-settings) for the type, role, and feature choices.

6. Under **Key and feature time**, select `event_id` as the primary key.
7. Select `Static` for the feature time policy.
8. Open **Conversions and source mappings**. Add a column mapping with target name `reading` and source name `value`.
9. Select **Review Table**. Check the definition, then select **Create Table**.

</TabItem>
<TabItem value="k8s">

Set `WORKSPACE` to the namespace that contains `fixture`. Copy the manifest into `events.yaml`.

<CodeBlock language="yaml" title="events.yaml">{tableYaml}</CodeBlock>

For the fields under `spec`, see [table settings](#table-settings) and [CSV column mappings](#csv-column-mappings). For the Kubernetes type and resource name, see [table fields](/user/create-a-table/#table-fields).

```bash
kubectl create -n "$WORKSPACE" -f events.yaml
```

</TabItem>
<TabItem value="curl">

Set `PROKRUST_URL` to your installation’s HTTPS origin. Set `PROKRUST_TOKEN` to your Kubernetes bearer token. Set `WORKSPACE` to the namespace that contains `fixture`.

`namespace` and `name` identify the table. Use its connection’s workspace. The `CreateTable` method selects the resource type. </TabItem>

### Table settings

| Field | Why this value |
| --- | --- |
| `spec.source.connectionRef` | The reference points to `fixture`. Its `apiVersion`, `kind`, and `name` must match the connection. To read another synthetic connection, change the name. |
| `spec.source.selector` | The selector tells that connection which dataset to read. Its `schemaVersion` selects the connector’s `v1` selector format. Its `config.dataset` must be `events`, the only dataset this release provides. [Selector fields](/reference/connectors/synthetic/1.1.0-rc.1/#table-selector) |
| `spec.columns[]` | Each entry declares a table column. `name` is the name that queries use. `physicalType` is the stored type. `semanticType` is the column’s role. The string ID identifies a row. The floating-point reading is a numerical measurement. [Column and type choices](/user/create-a-table/#columns-key-and-time) |
| `spec.columns[].feature` | `true` makes `reading` available as a model feature. Use `false` for `event_id` to keep the identifier out of the feature set. |
| `spec.primaryKey` | `event_id` names the declared ID column that uniquely identifies each row. Choose another ID column if it identifies your rows. |
| `spec.featureTimePolicy` | `Static` makes the reading independent of event time. For time-dependent features, declare the generated `event_time` column and choose `RowEventTime`. [Time policy and event-time field](/user/create-a-table/#columns-key-and-time) |

### CSV column mappings

`spec.ingestion` configures source parsing and conversion. Its `columns` list contains one entry because only one table column has a different name from its CSV header.

| Field within `spec.ingestion.columns[]` | Which name to use |
| --- | --- |
| `name` | The **table column**. Set it to `reading`, the name declared in `spec.columns`. If you rename that column, update this mapping. |
| `source.name` | The **CSV header**. The generator writes `value` in the file. Keep this value when you rename the table column. |

The reader matches `event_id` by name without a mapping. The default CSV settings read the first line as the header. [Ingestion fields and defaults](/reference/kubernetes/data.prokrust.ai/v1beta1/table/#ingestion)

## Verify the stored definition

<ReadTable name="events" />

Check that `spec.source.connectionRef.name` is `fixture` and `spec.source.selector.config.dataset` is `events`. Confirm that `spec.primaryKey` is `event_id` and the source for `reading` is `value`. These checks verify the saved configuration. A snapshot reads the source rows.
